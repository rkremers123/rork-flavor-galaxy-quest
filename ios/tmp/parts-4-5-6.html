PART 4: Food Management System

Overview: System for users to log foods, manage their food list, search/add custom foods, and organize foods by sensory attributes.

Feature 4.1: "No Longer Eats" Long-Press Menu

Mark Food as "No Longer Eats"

Purpose: If a kid stops eating a food they previously tried, parents can mark it as regressed.

Interaction:

  • Long-press on any food in the food list
  • Context menu appears with options:
    • "Move to Regression" (red option)
    • "Edit" (blue option)
    • "Delete" (gray option)
    • "Cancel" (back button)
  • If "Move to Regression" tapped:
    • Food moves to a "Regression Tracker" section
    • Timestamp recorded (when regressed)
    • Parent sees warning: "Regression detected - [Food] was previously eaten but no longer accepted. This is normal - SOS may help restore it."

Data Model:

food: { id: "apple_1", name: "Apple", currentPhase: "TASTE", // currently eating previouslyEaten: true, regressions: [ { date: "2026-03-15", phase: "TASTE", notes: "Child refused at lunch" } ], lastLoggedDate: "2026-03-10" }

Feature 4.2: Bridge Food Suggestions

Smart "Bridge Foods" Recommendations

Purpose: After 10 foods logged, app suggests "bridge foods" - similar foods that might help progress.

When Triggered: After kid logs 10 foods in current planet, weekly (every Monday).

How It Works:

  • Algorithm analyzes logged foods by sensory attributes (texture, flavor, temperature)
  • Finds foods with similar attributes kid already accepts
  • Suggests 2-3 "bridge foods" in a banner notification:
    • Heading: "Ready for Bridge Foods?"
    • Subheading: "Based on foods [Child] already enjoys..."
    • Shows suggested foods with why (e.g., "Similar to Apple but softer")
    • Button: "Add to Foods" or "Skip"

Example: Kid tried: Apple (crunchy, sweet), Carrot (crunchy, sweet). App suggests: Pear (crunchy, sweet but slightly softer).

Feature 4.3: Food Search & Custom Food Addition

Search & Add Custom Foods

Purpose: Let parents search existing food database or create custom foods.

UI Flow:

  • Search bar at top of Foods tab: "Search or add food..."
  • If user types and matching foods found: Show results (Apple, Apples - fresh, Applesauce, etc.)
  • If no matches: Show "Add custom food" prompt
    • Button: "+ Add '[food name]' as custom food"
    • Tapping opens dialog with fields:
      • Food name (pre-filled with search term)
      • Sensory attributes selector (Texture, Flavor, Temperature)
      • Cancel / Save button

Feature 4.4: FAB Button for Adding Foods

Floating Action Button (FAB) - Add Custom Food

Purpose: Quick access to add custom foods or search from anywhere in Foods tab.

Appearance:

  • Circular button, bottom-right corner of Foods tab
  • Icon: "+" symbol in white, color: #667eea (primary purple)
  • Size: 60px diameter
  • Shadow: Subtle drop shadow for depth
  • Animation on tap: Scale 1.1x, then back to 1.0x

On Tap: Opens search/add food dialog (same as search bar interaction).

Feature 4.5: Sensory Attribute Selection for All Foods

Sensory Attributes Tagging

Purpose: Every food has sensory attributes (texture, flavor, temperature) to help with bridge food suggestions and sensory profile.

When User Adds Food: Dialog shows 3 attribute categories:

  • Texture: Multi-select (can choose multiple)
    • Crunchy, Soft, Chewy, Liquid, Mushy, Mixed
  • Flavor: Multi-select
    • Sweet, Salty, Savory, Sour, Bitter, Bland
  • Temperature: Single select
    • Hot, Cold, Room Temp

Storage:

food: { name: "Apple", sensoryAttributes: { texture: ["crunchy", "firm"], flavor: ["sweet"], temperature: "room_temp" } }

Feature 4.6: Foods List Sorting Toggle

Sort Foods by Category

Purpose: Toggle button to sort foods by different criteria.

Sort Options:

  • By Phase (LOOK → TOUCH → SMELL → LICK → TASTE)
  • By Bridge (Bridge foods first)
  • By Texture (Group by: Crunchy, Soft, Chewy, etc.)
  • By Flavor (Group by: Sweet, Salty, Savory, etc.)
  • By Date Added (Newest first or Oldest first)

UI: Toggle icon at top-right of Foods list. Tap to cycle through sort modes. Current sort shows in header.

PART 5: Progress Tracking & Streaks

Overview: Visual tracking of daily engagement, sensory progression, and streak motivation mechanics.

Feature 5.1: Calendar View with Visual Coding

Calendar Progress Tracker

Purpose: Show kid's daily engagement over month/year with visual indicators.

Display: Tab in app: "Progress Calendar"

Layout:

  • Month view with day grid (standard calendar layout)
  • Each day shows a colored circle indicator:
  • Green (#28a745): Food logged that day
  • Gold/Star (#d4af37): Milestone achievement that day (planet unlocked, phase completed)
  • Empty/Gray: No activity that day
  • Tap on day to see what was logged that day (popup shows foods + phases)
  • Month/year selector at top to view past months

Feature 5.2: Streak Mechanic with Fire Icon

Daily Streak Counter

Purpose: Motivate consistent daily logging. Duolingo-style streak.

How It Works:

  • Any food logged in a day = +1 day to streak
  • Miss one day (no foods logged) = streak resets to 0
  • Display: Fire emoji 🔥 + number (e.g., "🔥 7" = 7-day streak)
  • Location: Visible at top of Journey tab, in Quest view, and in parent dashboard
  • Color changes: Gray (0 days) → Cyan (1-7 days) → Gold (8-30 days) → Rainbow gradient (30+ days)

Data Model:

user: { streak: { currentStreak: 7, longestStreak: 14, lastLoggedDate: "2026-03-15", streakStartDate: "2026-03-09" } }

Feature 5.3: Morning Notifications (8 AM)

Daily Streak Reminders

Purpose: Remind user to log a food to keep streak alive.

When Sent: 8 AM (device timezone, customizable by parent)

Conditions:

  • Only send if streak ≥ 3 days (don't nag on early streaks)
  • Only send if no food logged yet today
  • Don't send if streak is 0 (child isn't engaged yet)

Notification Text: "[Child's name]'s streak is at 🔥 [number]! Can you log a food today?"

Settings: Parent can customize time or disable notifications entirely.

Feature 5.4: Weekly Recap

Weekly Progress Summary

Purpose: Celebrate weekly progress and show engagement metrics.

When Delivered: Sunday evening (configurable) OR in-app banner at start of week

Content:

  • Foods logged this week: X
  • Phases progressed: [if any]
  • Current streak: 🔥 [number]
  • Personal best: [longest streak on record]
  • Celebratory message: "Great week, [Child]! Keep exploring!"

Delivery: Push notification + in-app banner

Feature 5.5: Monthly Detailed Report

Monthly Progress Report

Purpose: Detailed analytics for parents to track real progress and sensory regression patterns.

When Delivered: Auto-sent to parent on 1st of each month

Content (Parent Email/In-App Report):

  • Engagement Metrics:
    • Foods logged this month: X (vs last month)
    • Days active: X/30
    • Longest streak: 🔥 [number]
  • Sensory Profile:
    • Most common textures tried: Crunchy (12), Soft (8), Chewy (5)
    • Most common flavors tried: Sweet (10), Salty (4)
    • Temperature preferences: Room temp (15), Cold (3), Hot (2)
  • Phase Progression:
    • Current phases by planet (e.g., "Base Camp: TASTE, Sensory Grove: TOUCH")
    • Time spent in each phase (e.g., "LOOK: 5 days, TOUCH: 8 days")
  • Regression Detection:
    • Foods no longer accepted: [list with dates]
    • Pattern analysis: "No regression detected" OR "2 foods regressed - this is normal"
    • Recommendation: If regression detected, reassure parent and suggest continuing SOS

Feature 5.6: Therapist PDF Export

Export Report for SLP/OT

Purpose: Let parents download PDF to share with therapist.

Content: Same as monthly report + chart of phase progression over time

Format: PDF with Flavor Galaxy branding

Access: Button in Progress tab: "Export for Therapist" → generates PDF → opens share sheet to email/send
